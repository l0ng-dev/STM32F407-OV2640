## 1. 阶段目标与边界

本阶段在现有 `BSP/SCCB` 和 `BSP/OV2640` 基础上完成 OV2640 寄存器初始化，包括硬件复位、软件复位、Sensor Bank 切换、DSP 配置和 RGB565 输出格式设置。

本阶段没有启动 DCMI/DMA，没有创建图像缓冲区，也没有实现 JPEG、LCD 图像显示或 USART 图像发送。

## 3. 初始化流程

```text
SCCB_Init()
    ↓
OV2640_Init()
    ├── PWDN 退出掉电
    ├── RESET 硬件复位
    ├── 切换到 Sensor Bank
    ├── COM7 软件复位（0x12 = 0x80）
    ├── 等待 50 ms
    ├── 读取并校验 PID/VER（0x26/0x42）
    ├── 写入 178 组 UXGA Sensor/DSP 基础配置
    └── 写入 14 组 RGB565 输出格式配置
    ↓
再次读取 PID/VER（不再次复位）
    ↓
USART1 输出初始化结果
```

`OV2640_Read_ID()` 不再执行硬件复位。这样在 `OV2640_Init()` 完成后复读 PID/VER 时，不会清除刚写入的初始化配置。

所有 SCCB 操作均检查返回值。寄存器表写入遇到首个 NACK 或超时便停止，主流程输出 `OV2640 Init Failed` 后继续进入主循环，不会因摄像头错误进入死循环。

## 6. USART1 测试方法

1. 检查摄像头供电、公共地、SCL/SDA、PWDN 和 RESET 连接。
2. USART1 使用 PA9/PA10，串口工具设置为 115200 baud、8 data bits、1 stop bit、no parity。
3. 编译、烧录并复位开发板。
4. 正常时预期输出：

```text
OV2640 PID: 26
OV2640 VER: 42
OV2640 Init OK
```

失败时至少输出：

```text
OV2640 Init Failed
```

附加状态码含义：`1` 为 SCCB 参数异常，`2` 为 NACK，`3` 为总线超时，`4` 为芯片 ID 不匹配。

建议连续复位测试至少 10 次。如果偶发 NACK，使用逻辑分析仪检查软件复位后的 50 ms 等待、SCL/SDA 上拉和 ACK 波形。

## 8. 下一步 DCMI 准备事项

完成 `OV2640 Init OK` 实机验证后再进行以下工作：

- 明确首次采集采用 RGB565 还是后续切换 JPEG，避免传感器格式与 DCMI 配置不一致。
- 结合 OV2640 输出波形确认 PCLK、HSYNC、VSYNC 极性。
- 核对 D0-D7 与 STM32 DCMI 数据引脚连接顺序。
- 为 1600 × 1200 RGB565 评估带宽和存储需求；该完整帧约 3.84 MB，不能直接放入 STM32F407 片内 SRAM。
- 首次 DCMI 验证建议先增加较小分辨率配置，再设计 DMA 可访问的 SRAM 分块或行缓冲方案。
- 图像缓冲区不得放入 Cortex-M4 CCM RAM。
- 设计 DCMI 帧完成、DMA 错误和缓冲溢出处理后，再启动采集。
