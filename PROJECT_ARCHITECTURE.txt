F4Camera 工程架构说明
=====================

工程在 STM32F407ZGT6 上使用 OV2640、FSMC LCD 与外部 SRAM。当前包括 RGB565
LCD 预览和 JPEG/VOFA+ 模式；手势模型尚未实现。最近修改的构建与实机状态以
F4Camera边缘AI项目交接报告.md 为准，v1.1.0 的历史结果见 PROJECT_STATUS.md。

1. 模块职责
-----------
Core：CubeMX 生成初始化；main 在 FSMC 和 USART2 初始化后运行 SRAM 自检，
调用 CameraApp_Init()，主循环依次调用 CameraApp_Process() 和 Vofa_Process()；
DCMI 帧、错误回调仅转发。生成文件中的用户修改只放 USER CODE 区。

BSP/SRAM/sram_test.c：临时 1 MiB 全量破坏式 CPU 读写与字节通道测试；
保存结果供 SRAM_TestPassed() / SRAM_ReportResult() 使用，不负责初始化 FSMC。
BSP/Camera/camera.c：配置、启动和停止 DCMI/DMA，保存帧结束及错误快照。
BSP/OV2640/ov2640.c、BSP/SCCB/sccb.c：传感器配置和 SCCB 总线。
BSP/LCD：LCD 初始化、寄存器与绘图；FSMC 初始化由 CubeMX 负责。

Application/Camera/camera_app.c：按键、模式切换、采集调度与运行状态。
Application/JPEG/jpeg_capture.c：64 KiB JPEG 缓冲、采集状态与 SOI/EOI 解析。
Application/VOFA/vofa.c：VOFA+ FireWater 图片包、USART2 阻塞分块发送、
printf 行队列和串口故障锁定。公共接口为 vofa.h，均由主循环调用。

2. 数据流和所有权
-----------------
RGB565：OV2640 -> DCMI Snapshot -> DMA -> LCD GRAM（固定目标）。
JPEG：OV2640 -> DCMI Snapshot -> DMA -> 外部 SRAM 0x68000000（64 KiB）
      -> JPEG 边界解析 -> VOFA+ 前导帧和 JPEG -> USART2 -> 上位机。

JPEG 缓冲在 DMA 采集期间由 DMA 写入；帧结束、停止 DMA 后由 CPU 解析，
再由 USART2 发送。完整帧发送结束前不得重启采集或改写缓冲。模式切换按
停止 DCMI/DMA -> 配置传感器和 DCMI -> 重建 DMA -> 启动采集的顺序执行。
WKUP 进入 LCD，KEY0 进入 JPEG。当前传感器 JPEG 模式 CLKRC 为 0x01，
为外部 SRAM 采集阶段的试验值，不代表已完成长期时序验证。

3. 串口与日志
-------------
USART2 为 921600 8N1、发送模式；VOFA+ 选 FireWater，图片通道 img0。
Vofa_SendJpegChunk() 发送一次前导帧和分块负载；image_active 期间，
Vofa_Process() 不发送日志。printf 以整行入队，12 行、每行最多 128 字节（含换行与截断标记）；
满队列丢弃并计数，过长行以 ~ 标记。每秒最多一条 sram 数值帧，依次为
SRAM 测试结果、JPEG 字节数、采集/解析毫秒、发送毫秒、首次观察 DMA 进展
毫秒、进展至帧结束毫秒；最后两项为轮询近似，-1 表示无可靠测量。

发送中途出现 HAL 错误后锁定串口流，避免将后续字节塞入不完整的图片包；
复位接收端解析状态及目标板后重新开始。串口本身故障无法保证通过自身报告。
DEBUG_VERBOSE 默认为 0；中断和回调中禁止 printf 和阻塞串口传输。

4. 配置及维护边界
-----------------
F4Camera.ioc 是外设配置源；CubeMX 由用户操作。Bank 3 连接外部 SRAM，
Bank 4 连接 LCD，共用 FSMC 时钟和部分引脚，不能随意反初始化任一 Bank。
当前自检每次启动覆盖整块 SRAM，正式存放 AI 缓冲区前必须调整。JPEG 是压缩流，
后续 AI 输入格式、模型和缓冲区生命周期仍待数据与模型评估。未经明确授权
不烧录、不复位目标板；编译、历史现场结果和当前硬件验证分别记录。
