# STM32F407 OV2640 摄像头与手势识别

基于 STM32F407ZGT6、OV2640、FSMC LCD 和板载 1 MiB 外部 SRAM，实现 LCD 预览叠加手势识别，以及独立的 JPEG/VOFA+ 传图。

## 使用方式

| 操作 | 行为 |
|---|---|
| 上电或复位 | 初始化 FSMC 后对 1 MiB 外部 SRAM 做破坏性自检，随后显示待机页 |
| WKUP（PA0，高有效） | 进入 320×240 RGB565 预览，叠加三类手势识别结果 |
| KEY0（PE4，高有效）按下并松开 | 进入 320×240 JPEG 连续传图 |

待机页显示就绪或故障状态及按键用途。LCD 控制器由程序读取 ID；用户曾记录本板 ID 为 `0x7789`，未识别时不启动 LCD 预览。SRAM 自检会覆盖整个器件，只能在 FSMC 初始化后、采集和推理使用 SRAM 前执行。

### 串口

| 用途 | 配置 | 使用方式 |
|---|---|---|
| 日志 | USART1，PA9 TX，115200/8N1 | PA9 连接 3.3 V USB 转串口模块 RX、共地；文本行以 CRLF 结尾 |
| 图片 | USART2，PA2 TX，921600/8N1 | VOFA+ 使用 FireWater，图片控件绑定 `img0` |

USART2 图片包含二进制数据，不适合在普通文本窗口查看。USART1 的 PA10 已配置为 RX，但查看日志不需要连接；两个接收程序使用各自对应的串口。旧 USART1 单帧 `P/I/T` 验证模块和电脑工具仍保留，但当前两种模式没有调用入口；如以后重新接入，应协调日志和二进制报文，避免混流。

## 主要数据流

```text
OV2640 RGB565 → DCMI / DMA2 Stream1 → 外部 SRAM 双帧缓冲
    ├─ RGB565 预处理 → 手势模型同步推理 → 三类结果
    └─ 叠加结果 → DMA2 Stream0 分两段写 LCD
OV2640 JPEG → DCMI / DMA2 Stream1 → 外部 SRAM 双缓冲
    → SOI/EOI 解析 → USART2 → VOFA+
日志 → 有界队列 → USART1
```

预览采集与 LCD 显示使用不同帧缓冲；推理的节点回调在调用线程推进预览。显示的耗时包含回调中的预览服务，不是纯推理耗时。JPEG 发送一块缓冲的同时采集另一块，发送完成前不会复用正在发送的缓冲。

## 工程与构建

- `Core/` 和 `F4Camera.ioc`：CubeMX 外设配置、初始化和回调入口；生成文件的自定义代码位于用户代码区。
- `Application/Camera/`：模式调度、RGB565 预处理、手势推理、字模及保留的验证接口。
- `Application/JPEG/`、`Application/VOFA/`：JPEG 帧管理、图片协议和日志输出。
- `BSP/`：DCMI、OV2640、SCCB、LCD 和外部 SRAM 适配；地址划分见 `BSP/SRAM/sram_layout.h`。
- `AI/Model/` 和 `AI/Middlewares/`：生成模型和匹配运行库；许可见 `AI/LICENSE.txt`。LCD 汉字子集许可见 `BSP/LCD/OFL-NotoSansSC.txt`。
- `Tools/`：保留的单帧预处理和推理对照工具，依赖旧验证入口。

使用 Keil MDK 打开 `MDK-ARM/F4Camera.uvprojx`；本机验证使用 ArmClang 6.24。CubeMX 配置及 Keil 下载由使用者操作。更多实现说明见 [项目架构说明](项目架构说明.md)，v1.1.0 历史记录见 [项目状态与验证记录](项目状态与验证记录.md)。

## 模型与内存

模型为预训练 ShuffleNet V2 x0.5，经自采数据及板端输入微调；输出类别顺序为 `no_hand / palm / fist`。RGB565 经缩放到 160×120、上下黑边填充至 160×160、ImageNet 归一化和量化，形成 INT8 NCHW 输入。当前取三类中最高分，未实现其他手势拒识；置信度不保证预测正确。QDQ 模型可能包含浮点运算，不能称为全 INT8。

| 外部 SRAM 用途 | 起始地址 | 大小（字节） |
|---|---:|---:|
| JPEG 缓冲 1 | `0x68000000` | 65,536 |
| 模型第二激活区 | `0x68010000` | 76,804 |
| RGB565 缓冲 1 | `0x68022C20` | 153,600 |
| 量化输入 | `0x68048420` | 76,800 |
| JPEG 缓冲 2 | `0x6805B020` | 65,536 |
| RGB565 缓冲 2 | `0x68074020` | 153,600 |

模型第一激活区 102,400 B 位于片内 RAM，权重位于 Flash；Keil 启动栈配置为 4 KiB。外部 SRAM 必须在 FSMC 初始化和自检后使用，采集或推理期间不得重新执行全量自检。

## 故障与验证边界

- 采集、推理或发送故障会尝试停止当前模式；只有确认相关 DMA 停止且 LCD 可用时才绘制故障页。USART2 图片流在发送失败后锁定，避免后续数据混入半帧；重新打开 VOFA+ 并复位 MCU 后再试。日志通过独立的 USART1 输出。
- 2026-11-08 的本地 Keil 整工程重建记录为 0 errors、0 warnings；Code=90,424、RO-data=395,552、RW-data=16,192、ZI-data=111,004 B。用户确认此前字库、DMA 停止检查和故障提示通过，以及 USART1 日志换行通过。上述结果不代替长期测试或完整异常注入。
- LCD + AI 的早期双外部激活区实验曾发生 DCMI overrun；第一激活区移回片内后用户反馈画面及识别正常。共享 FSMC 的长期并发稳定性和实际栈水位尚未验证。
- 预处理真实帧曾与电脑参考逐元素一致；板端与 ONNX 的有限样本有完全一致及约一个量化步长差异的记录，不能据此推断模型总体准确率。开发集已用于选模，A04 保留作后续独立于选模的有限场景评估。
- 补光模块的现有测量与 STROBE 支路接通、外部 FLASH 支路断开相符；用户决定不改焊，固件未实现补光控制。
